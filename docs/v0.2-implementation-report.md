# AIPE Academy v0.2 — implementation report

Date: 2026-10-20. Scope: the full v0.2 development task (knowledge
architecture, MIT OpenCourseWare academic baseline, curriculum, AI tutoring,
Codex/Claude Code integration, website synchronisation). Branches:
`claude/aipe-academy-v0.2` (this repository) and `claude/academy-v0.2-sync`
(Spirit-Connect-AIPE-Labs), both pushed to the `MrCoconut616` forks because
the upstream `FulongLi` repositories are read-only for this account. Nothing
was merged or deployed; every claim below names the evidence behind it.

## 1. Executive summary

- **Knowledge architecture.** Four canonical domains (`foundations`,
  `power-electronics`, `power-systems`, `renewable-energy`), 26 tracks and 57
  modules with bilingual labels and acyclic cross-domain prerequisites in
  `curriculum/taxonomy.json`; lesson records extended with module, concept
  (language mapping), format, labs and academic references; three deterministic
  generated outputs; all eleven v0.1 URLs preserved and pinned by tests; the
  seven-stage power-electronics path with G1/G2/G3 preserved as a learning path.
- **MIT OCW baseline.** All 22 candidate courses verified live (HTTP 200, title
  and term matching), their public syllabi and resource listings read, topics
  mapped onto modules with evidence URLs by a mapping agent, a fact-checker and
  a curriculum reviewer per course; 52 of 57 modules have at least one course
  mapped; gaps recorded, including the modern grid topics the baseline does not
  cover. Licensing rules codified; only metadata and short listing titles are
  stored.
- **Curriculum.** One complete thirteen-section lesson per domain, each with a
  standard-library Python lab whose default output equals the worked examples,
  and 223 lab unit tests. Existing Buck materials preserved and given Academic
  References sections.
- **AI tutoring and agents.** Shared tutor workflow (seven workflows), one
  shared skill for Codex and Claude Code, a Claude Code plugin and marketplace,
  a Codex repository entry, and a companion command with local learning
  records. Verified with the real Claude Code and Codex CLIs.
- **Website.** Sync consumes the generated graph and references, renders
  lesson resources and external academic references panels, renames
  `renewables` to `renewable-energy` with redirects, and validates everything
  in CI. Fork CI builds the Jekyll site; no live deployment was performed.
- **Quality.** 293 Academy tests and 58 website tests pass locally; the
  `generated/` and `references/*.md` files are checked for staleness in CI.

## 2. Architecture and directory structure

See `docs/architecture.md` for the full description. Key files:

```text
curriculum/taxonomy.json      Domain → Track → Module (57), learning paths, G1/G2/G3 gates
curriculum/catalogue.json     15 records (11 v0.1 + 4 v0.2), schema 0.2
schemas/                      lesson.schema.json (0.2), taxonomy.schema.json, academic-reference.schema.json
scripts/build_catalogue.py    validation + generated/lessons.json, knowledge-graph.json, academic-references.json
scripts/build_reference_docs.py   renders references/mit-ocw-baseline.md and academic-coverage-map.md
scripts/verify_academic_sources.py  network verification (on demand)
references/                   mit-ocw-catalogue.json, mit-ocw-verification.json, mit-ocw-coverage.json, academic-source-guidelines.md
curriculum/<domain>/<track>/  four v0.2 lessons; v0.1 stage folders untouched
labs/<domain>/*.py            four new labs; labs/buck_open.py kept (exit-code convention aligned)
skills/aipe-academy/          SKILL.md, scripts/academy.py, references/commands.md, agents/openai.yaml
.agents/skills/aipe-academy/  Codex repository entry (points at the shared skill)
.claude-plugin/               plugin.json, marketplace.json
docs/                         architecture, curriculum-guide, plugin-installation, website-integration, this report
tests/                        9 suites, 293 tests
.github/workflows/validate.yml  build/doc staleness, tests, labs, companion command, claude plugin validate/list
```

Dimensions kept apart: academic domain (taxonomy.domains), knowledge
taxonomy (tracks/modules with `requires`), learning progression
(`learning_paths`). Module status is derived from attached lessons
(available / draft / outline / planned).

## 6. Engineering labs and numerical validation results

All labs: Python 3.10 standard library, SI units, assumptions and limitations
in every result, `ValueError` → exit code 2 on invalid input, deterministic
JSON. Default runs on this machine (Windows 11, CPython 3.10.11): all exit 0 in
under 0.1 s.

| Lab | Default result (analytical/numerical teaching model) | Tests |
| --- | --- | --- |
| `labs/buck_open.py` | D = 0.5, I = 2.5 A, Δi = 0.4 A, I_min = 2.3 A | 2 |
| `labs/foundations/dc_circuits.py` | 6 V/300 Ω → 20 mA, 0.12 W, 216 J (30 min); loaded divider 6 V → 4 V (−33.3 %); nodal solver KCL residual ≈ 1e-19 A | 67 |
| `labs/power-electronics/buck_switching.py` | 12.0000 V mean, ripple 0.40006 A / 5.0014 mV, CCM, settled after 1427 periods; DCM detected at R = 120 Ω (14.834 V vs analytical 14.833 V) | 39 |
| `labs/power-systems/three_phase.py` | 400 V, 10 + j5 Ω wye: 20.656 A, 12 800 W, 6400 var, pf 0.8944 lagging; PF correction to 0.95: C_Y = 43.6 µF; per-unit on 100 kVA/11 kV: Z_base 1210 Ω | 62 |
| `labs/renewable-energy/pv_model.py` | 60-cell synthetic module: V_mp 29.632 V, I_mp 8.288 A, P_mp 245.58 W, FF 0.7284; β(V_oc) −0.3165 %/K; P&O tracking efficiency 0.9989 | 55 |

No hardware validation is claimed anywhere; each lesson states this.

## 13. Known limitations and unfinished items

- 32 of 57 modules are planned (no lesson) and 14 are outlines; the four
  complete lessons are English only. Chinese versions of the new lessons are
  not written; translation availability is shown honestly.
- Labs are analytical/numerical teaching models; no switching-simulation
  (ngspice) or hardware comparison exists yet.
- Interactive, model-driven tutoring sessions inside Codex and Claude Code were
  not executed; validation, loading and discovery were.
- Marketplace installation from `FulongLi/AIPE-Academy` works only after the
  upstream merge; until then use `--plugin-dir` or the fork.
- No live website deployment; CI on the fork is the build evidence. The
  website lock pins a fork commit, as the earlier v0.1 integration did.
- The academic coverage map is large (~400 KB) because it carries the per-course
  topic outlines as evidence; the top table is the summary.
- Two taxonomy suggestions from the mapping review were adopted (`ps.power-flow`
  requires `f.linear-algebra`); others are recorded in the coverage file for a
  maintainer decision.
- Codex CLI 0.163.0 was installed globally with npm on the development machine
  for the discovery test.
